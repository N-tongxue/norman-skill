# 快速批量制图

所有页面遵守 SKILL.md 的“原图优先与禁止新增插画”，该规则优先于本文件中旧有整页生成或修图限制：尽量覆盖正文全部 Figure；页少优先两张相关图一页，页多优先一张图一页；禁止新增 AI 插画，仅允许基于原文的简洁流程图。AI 为科研原图留空位，最终本地直接置入原始文件，禁止重绘。

目标是减少逐页重复决策、提示词手写、工具空等与过度返工；科学准确、AI 排版底稿加原图保真组装、真实原图和高清要求保持；技能水印只在封面添加。不承诺模型本身的固定速度或未实测的加速倍数。

## 1. 全部内容与素材一次准备

同步规划成品密度：结果页通常 120–180 字，概览与总结 160–220 字，以主图加解释框、对照框及结论带填充有效画布。每页提示词写定文本框位置、填充色、字色与内边距；保真置入和可编辑重建后必须保留相同布局，不退化为大面积白底加少量漂浮文字。

精读完成后固定四部分架构：封面 1 页、研究背景／技术路线／数据方法合并 1 页、核心结果 N−3 页、研究创新／研究结论／研究启示合并 1 页。确定各页中心观点、可见文案、图表面板、整页构图与时间；先选与证据匹配的流程／对比／汇聚关系，再在 image_brief 或 visual_logic 中写清起点、阅读方向与结论收束位置；两张合并页在 topics 中列全三个主题，并在 image_brief 写明对应文案与整体构图。一次准备所有需要的高分辨率论文图和封面首页图，集中查看这些参考文件，避免每生成一页都重新阅读 PDF、裁同一张图或问用户。

一次写完 style.md 和 deck.json 中所有页的 `image_brief` 与 `reference_images`。style.md 只保留必要的统一视觉规范，通常约 200–400 中文汉字；不复制整个技能或论文分析，不包含两行水印原文或“每页都加水印”的旧规则。正文 image_brief 也不能带技能水印原文。image_brief 使用简洁、可执行的页面设计说明，包含全部必要可见文案，不写长篇内心分析：

```json
{
  "number": 5,
  "section": "核心结果",
  "title": "经过原文核实的结果标题",
  "image_brief": "中心观点：……。逐字文案：标题……；解读……；限定……；来源……。输入图像1是论文Fig.2b原图，应完整保留。布局：真实结果图约占内容区域三分之二，右侧短句解释；明确主次和阅读顺序。",
  "reference_images": ["figures/fig-2b.png"]
}
```

这只是单页字段形状，仍需 SKILL.md 规定的其他字段与全部页面。`reference_images` 仅列真实本地图像；无参考图的页面用空数组。参考图角色必须写进 image_brief。封面脚本自动把 cover_paper_image.path 放为输入图 1。所有页共享文字风格规范与用户已有风格参考，不将「前一页必须先生成并美化合格」作为依赖。

## 2. 一次编译所有提示词

```powershell
& "$S/bin/windows-x64/norman-paper2ppt.exe" prepare-image-batch "$OUT/deck.json" --style "$OUT/style.md"
```

脚本在生成图像之前运行，不要求最终 slides/ 已存在；不要在这一步运行会要求最终图片存在的 `norman-paper2ppt validate`。脚本一次校验内容计划、编译每页完整提示词，并输出：

- `prompts/NN.txt`：每页完整提示词，共享视觉规范由脚本复用；仅封面注入两行水印，其余页面加入无技能水印约束。
- `image-batch.json`：每页独立任务、真实内置工具参数、参考图路径／指纹、job_id 与期望保存位置。
- `prompts/batches/<hash>.json`：保留该批提示词与任务的快照。

脚本不调用模型、不读取 API 密钥、不生成图片。save_as 是拿到真实结果后复制／保存文件的位置，**不是图像工具的参数**。不要把整条 job 当工具入参；只传 `job.arguments`。参考内容或提示词改变时 job_id 改变，防止把旧结果误当新版本。

## 3. 连续提交，允许时有限并发

当前内置工具没有“整套 deck 一次生成”的接口。每页仍独立调用 image_gen；**批量意味着连续编排这些独立调用**。不能用不存在的 batch 参数、`n`、多页拼图或切换到需密钥的 CLI 来假称批量。

functions.exec 可编排独立工具调用时，用有界并发，默认最多 3 个任务，仅限实际接口允许并发时；不能无界同时提交全套。若实际工具不允许并发或出现限流，降为 1 个并连续处理，保留已成功任务。不要为启用并发新建聊天、启动子代理或要求第四个用户选择。

先用实际可读文件工具读取 image-batch.json，将解析结果保存到 functions 的 store。例如在 exec 中调用 exec_command 读取实际绝对路径的 UTF-8 JSON，再 `JSON.parse(result.output)`，检查 exit_code 并 `store("norman_image_batch", batch)`；不要把完整提示词再打印给模型或用户。编排示例（替换 start 后运行，每批都必须完整 await）：

```javascript
// @exec: {"yield_time_ms": 120000, "max_output_tokens": 1200}
const batch = load("norman_image_batch");
const start = 0; // 从已保存进度中确定下一组待处理页，不固定重复第一页
const group = batch.jobs.slice(start, start + 2);
const results = await Promise.allSettled(group.map(async job => {
  const result = await tools.image_gen__imagegen(job.arguments);
  store(job.job_id, result);
  return { slide: job.slide, job_id: job.job_id, tool_returned: true };
}));
text(results.map((r, i) => ({slide: group[i].slide, status: r.status})));
```

上例只说明真实调用与返回结果保留；`fulfilled`／`tool_returned` 不证明生成成功。必须查看实际返回是否为工具错误，按真实路径或真实图像数据保存结果，然后才记录 `generated`。不得假定 result.path 等未核实的返回字段，也不要打印 base64。需要等待时按当前工具文档处理，不丢弃未完成的 Promise。

实际支持并发时优先采用固定 3 个工作者的滑动队列：每个任务返回并保存后立即取下一页，避免等待同组最慢页；用 Promise.allSettled 等待全部工作者结束。上面的两页示例仅为兼容性写法，不要求固定两页屏障。每组返回后及时保存图像，更新 generation-log.json：job_id、页号、真实调用状态、实际生成文件路径、错误。**组间只做持久化和进度检查，不插入逐页审美返工或可编辑重建**，立刻继续下一组；不要等上一页完成精修才能提交下一页。保存成功且 job_id 匹配的页不重复调用；失败页另列队列，核实真实状态后至多重试一次暂时性错误。未知状态先核实，不能盲目重复提交。

## 4. 整批审核与定点修正

整批初稿结束后统一检查缩略图和各页全尺寸图，一次列出所有必要修正。合格页直接锁定，保留原文件；同页多个已确认问题合并为一个明确的图像编辑指令，通常只做一轮问题页修正。修正页仍以单页独立任务编排、保留未改部分、保存新版本并复核。

不得为轻微色差或装饰偏好反复制图。错误数字、图表失真、文字错误、封面水印缺失、正文误带技能水印、封面首页位置错误、裁切或明显不可读必须修复，即使需要额外一轮；科学和可读性不能换取速度。全部合格后再统一组装 PPT 和可选可编辑版。讲稿在页面内容确定后集中撰写，可利用工具等待期间完成；不要阻塞待提交的图片。图片审核通过后立刻组装图片版，可编辑处理后置；不必等可编辑版完成才告知图片版已就绪。

QA 保留每批页数、实际并发方式、成功／失败／复用页和修正页。只有记录了真实开始结束时间才报告耗时，不把脚本编译成功说成图片已生成，不把编排示例说成已验证真实并发性能。
